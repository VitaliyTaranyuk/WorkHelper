# Исследование рынка: платформа управления AI-разработкой (мульти-проектный WorkTask)

> Дата: 2026-07-28. Статус: исследование, решения не приняты.
> Метод: анализ вторичных источников (обзоры, отраслевые отчёты, блоги вендоров,
> arXiv, профили компаний). **Ограничение:** большинство цифр — вторичные; там, где
> источники расходятся, расхождение зафиксировано явно. Перед принятием
> инвестиционных решений цифры со звёздочкой (*) требуют первичной проверки.

---

## 1. Постановка

Проверяемая гипотеза продукта:

> Мульти-проектная платформа, где «ядро инженерного метода» переносится между
> проектами, знания проекта живут в его репозитории, агент подключается любой
> (BYO agent), а система со временем сама предлагает улучшения метода на основе
> наблюдаемых повторов.

Вопросы исследования:
1. Есть ли рынок и сколько на нём платят?
2. Кто уже занимает соседние ниши и чем именно?
3. Какая часть гипотезы уже реализована конкурентами?
4. Что из гипотезы опровергается практикой?
5. Где остаётся незанятое место и что его защищает?

## 2. Рынок: размер и реальные деньги

### 2.1 Объём

| Показатель | Значение | Источник |
|---|---|---|
| AI code assistants, 2025 | $8.5 млрд | Grand View Research |
| AI code assistants, 2026 | $10.3 млрд | Grand View Research |
| Прогноз 2033 | $42.8 млрд (CAGR 22.5%) | Grand View Research |
| Альтернативная оценка 2025 | $4.2 млрд → $40.7 млрд к 2035 (CAGR 25.3%) | Astute Analytica |
| Enterprise AI coding agents, апрель 2026 | ~$9.8–11.0 млрд annualized | Gartner |

Расхождение базовых оценок вдвое (8.5 против 4.2) — типично для этой категории:
разные границы («ассистенты» против «агентов»). Вывод, устойчивый к расхождению:
**рынок двузначно-миллиардный и растёт на ~22–25% в год**.

### 2.2 Сколько реально платят за разработчика

| Позиция | Сумма |
|---|---|
| Совокупно (сиденье + токены) | $200–600 / dev / мес |
| Claude Code в enterprise | $150–250 / dev / мес; ~$13 / dev / активный день; 90% ниже $30/день |
| GitHub Copilot Enterprise | ~$60 / user / мес (с обязательным GHEC $21) |
| Cursor Business | $40 / user / мес |
| Devin (Cognition) | Core $20 / мес, Team $500 / мес, Enterprise — по запросу* |

*По Devin источники противоречат друг другу: одни дают Core $20 / Team $500 /
Enterprise, другие — Free / Pro $20 / Max $200 / Teams $80 + $40 за место.
Требуется проверка на сайте вендора.

Модель монетизации смещается: per-seat пока доминирует (66.4% рынка), но вендоры
переходят на usage-based из-за стоимости агентных прогонов.

**Следствие для нас:** бюджет на инструменты вокруг агента уже существует и он
крупный. Но он в значительной степени **уходит на токены**, а не на софт. Это
одновременно риск (кошелёк уже занят) и возможность (инструмент, который снижает
расход токенов, окупается арифметически, а не «по ощущениям»).

### 2.3 Реальная отдача (важно для честного позиционирования)

Данные DX по 400+ организациям:

* медианный прирост PR throughput: **+7.76%**
* среднее: **+13.1%**, типичный диапазон **5–15%**, 90-й перцентиль **43.9%**
* кодирование — лишь **14% времени** разработчика, что структурно ограничивает эффект

Против заявлений вендоров о «3–10x». Также зафиксированы шоки по счетам: с $29 до
$750/мес и с $50 до $3000/мес у отдельных пользователей при переходе на агентные
режимы.

**Следствие:** любые маркетинговые обещания кратного роста продуктивности —
проигрышная позиция. Продавать надо снижение переделок и стоимости, а не «10x».

## 3. Боль пользователей (подтверждена количественно)

Sonar «State of Code» 2026 и связанные обзоры:

| Боль | Доля |
|---|---|
| «Почти правильно, но не совсем» | 66% |
| Отладка AI-кода дольше ожидаемого | 45% |
| Галлюцинации/неточности | 64% |
| Качество кода | 53% |
| Нехватка контекста | 38% |
| Доверяют выводу AI | только 29% |
| Не доверяют полностью функциональной корректности | 96% |

Качество кодовой базы (GitClear, январь 2026):

* у активных пользователей AI **в 9 раз больше churn** (код, переписанный в течение 2 недель)
* churn вырос с 3.1% (2020) до 5.7% (2024), к 2024–2025 — 5.7–7.1% по индустрии

Отдельно зафиксировано: **все инструменты заметно хуже работают на существующих
кодовых базах**, чем на greenfield — агенты не понимают неявных конвенций и
недокументированных допущений.

**Следствие:** главная боль — не «агент не умеет писать код», а **rework**,
**недоверие** и **brownfield**. Продукт должен целиться именно туда.

## 4. Карта конкурентов: шесть слоёв

### Слой 1. Формат инструкций агенту (стандарт)

**AGENTS.md** — де-факто кросс-инструментальный стандарт: под управлением Agentic AI
Foundation (Linux Foundation), 60 000+ репозиториев, читается Claude Code, Codex CLI,
Cursor, Aider, Devin, Copilot, Gemini CLI, Windsurf, Amazon Q.

Критично важные эмпирические данные:

* файлы, **написанные человеком**: +4% к успеху задач, **−35…55% багов**
* файлы, **сгенерированные LLM**: −2% к успеху, **+23% к стоимости** — потому что
  дублировали то, что и так есть в репозитории

Инструменты синхронизации правил (`rulesync`, `ai-rules-sync`) уже существуют и
бесплатны: генерируют CLAUDE.md / .cursorrules / copilot-instructions.md и т.п. из
одного источника.

> **Вывод:** идея «компилировать правила под разных агентов» — не дифференциатор.
> Это уже commodity. Стандарт для интеграции выбран за нас: AGENTS.md.
> И главное: ценность даёт **неочевидное знание, написанное человеком**, а не объём
> автогенерённого текста. Автогенерация правил без человека — отрицательная ценность.

### Слой 2. Метод / spec-driven фреймворки (открытые, бесплатные)

| Инструмент | Лицензия | Звёзды* | Суть | Слабость |
|---|---|---|---|---|
| GitHub Spec Kit | OSS | ~90–93k | Specify→Plan→Tasks→Implement, «конституция» правил, 30+ агентов | спека как стартовый документ, дрейфует после начала кодогенерации |
| BMAD-METHOD | MIT | ~46.7k | 12–21 специализированный агент на весь SDLC, файловые хендоффы | «кувалда по ореху» для мелких изменений |
| GSD (Get Shit Done) | OSS | ~59–61k | мета-промптинг, свежий subagent с чистым контекстом на каждую задачу — против context rot | |
| OpenSpec | MIT | ~52k | delta-спеки (ADDED/MODIFIED/REMOVED), заточен под brownfield | нет управления worktree; документы статичны, дрейфуют |
| Kiro (AWS) | проприетарный | — | агентная IDE, три фазы, EARS-нотация, GA v1.0 (июль 2026) | избыточен для мелких правок |
| Tessl | проприетарный | — | Framework («тайлы» в .tessl/, любой MCP-агент) + Spec Registry (10 000+ спек библиотек) | ранняя зрелость |

*Звёзды расходятся между источниками на 2–4k — брать как порядок величины.

Зрелость метода описывают тремя ступенями: **spec-first** (спека выбрасывается) →
**spec-anchored** (спека живёт и эволюционирует) → **spec-as-source** (правится
только спека, код генерируется). Большинство инструментов застряли на первой.

**Ключевой нерешённый разрыв, названный всеми обзорами:** инструменты хороши при
ясной спеке вперёд и **проваливаются на итеративных изменениях** — «the fundamental
modification problem». Прямо адресуют его только OpenSpec и Tessl.

### Слой 3. Критика метода (обязательно учесть)

* Scott Logic: SDD оказался **в 10 раз медленнее** — 33 минуты и 2577 строк markdown
  ради 689 строк кода против 8 минут итеративного промптинга, **без выигрыша в качестве**.
* «Spec-Driven Development Is Waterfall in Markdown», «The Waterfall Strikes Back» —
  повторение ошибок, ради которых появился Agile.
* Накладные расходы масштабируются с размером задачи; **мелкие задачи страдают больше всего**.
* Академическая работа (arXiv 2606.04967) отмечает несогласованность процессных
  моделей между фреймворками и **дефицит эмпирической валидации**.
* Историческая аналогия, которую поднимают критики: провал Model-Driven Development.

**Следствие — жёсткое:** продавать «правильный процесс» нельзя. Процесс должен быть
**пропорционален размеру задачи** (мелкая правка — без церемоний) и обязан
доказывать себя цифрами. Продукт, навязывающий тяжёлый ритуал, встретит уже
сформировавшийся негативный консенсус.

### Слой 4. Control plane (кто владеет «единым окном»)

* **GitHub Agent HQ / Mission Control** (анонс Universe 2025, раскатка с начала 2026):
  назначение задач агентам **через репозитории**, custom agents через `agents.md`,
  сторонние агенты Anthropic / OpenAI / Google / Cognition / xAI, живые логи,
  вмешательство на ходу, параллельные сессии, self-hosted runners.
* **Linear**: нативные AI Agents с апреля 2026, входят в Plus/Enterprise **без
  метрируемой оплаты токенов**; двусторонняя синхронизация с GitHub.
* **Jira**: Agents в GA на Team '26; агент-ассистированные апдейты проектов с июня 2026.

**Это самая опасная зона.** Позиция «борд для агентных задач» атакована сверху
владельцем репозиториев и снизу — трекерами, у которых уже есть аудитория.

### Слой 5. Локальная оркестрация агентов (коммодити, деньги не пахнут)

Vibe Kanban (Apache-2.0; компания-разработчик Bloop **закрылась в начале 2026**,
проект живёт как OSS), Conductor (Mac, бесплатно), Claude Squad (AGPL), Sculptor
(контейнерная изоляция), Nimbalyst (MIT), Superset ($15/user/мес), Paneflow, Mux,
Opcode (больше не развивается), просто tmux+скрипты.

Явно зафиксированный обзорами пробел: **ни один из них не работает с несколькими
проектами и не держит постоянное знание о проекте между сессиями** — фокус на
worktree-изоляции внутри одного репозитория.

**Следствие:** сама по себе оркестрация — бесплатная и уже с одним трупом компании.
Строить бизнес на слое «параллельные агенты в worktree» нельзя. Но названный пробел
(мультипроектность + постоянное знание) — ровно то, куда мы целимся.

### Слой 6. Контекст и знание о коде (где реальные деньги)

* **Augment Code**: Context Engine строит граф знаний по кодовой базе (400 000+ файлов),
  BYO agent, 70.6% на SWE-bench.
* **Sourcegraph Amp**: поверх code graph — символы, ссылки, деревья зависимостей,
  кросс-репозиторные связи.
* **Tessl Spec Registry**: 10 000+ спек внешних библиотек против галлюцинаций API.
* Три конкурирующие философии: index-first (Cursor, Augment, Cody), agentic search
  (Claude Code), hybrid graph-augmented. **MCP — уже table stakes.**

Определение, которое стоит запомнить: context engine — это «предварительно
проанализированное, запрашиваемое понимание кодовой базы: цепочки зависимостей,
карты радиуса поражения, пробелы покрытия, границы владения».

## 5. Самообучение: уже реализовано — и это подтверждение, а не приговор

**Cursor BugBot** — прямая реализация механики, которую мы обсуждали, но в домене
код-ревью:

* читает реакции и комментарии ревьюеров на PR;
* **генерирует из сигнала правила**;
* кандидат становится активным правилом, накопив сигнал;
* правило **выводится из обращения**, если начинает получать негативную обратную связь;
* результат: resolution rate вырос с 52% на старте до **~80%** (апрель 2026).

**Edra** (март 2026, $30M Series A от Sequoia, выходцы из Palantir) — та же идея в
операционном домене: «Living Playbooks» подключаются к системам компании, читают
тикеты/письма/логи, реверс-инжинирят **как работа выполняется на самом деле**, и
предлагают улучшения. У HubSpot: 150 000 обращений → 600+ обновлений базы знаний,
−12% ручных хендоффов.

Академический фон 2026: MemRL, SelfMem, MemMA, Fine-Mem, DemoEvolve — активное
направление самоэволюционирующей памяти агентов. Есть и работы о рисках
(«Zombie Agents»: устойчивое вредоносное управление самоэволюционирующими агентами
через самоподкрепляющиеся инъекции).

**Выводы:**
1. Механика «сигнал → кандидат → правило → отзыв правила» **валидирована в проде** —
   это не фантазия.
2. Её уже делает крупный игрок, но **в одном домене (ревью) и внутри одного вендора**.
3. Никто не делает это **между проектами** и **поверх любого агента**.
4. Риск безопасности самоэволюции — реальный и изучаемый; человеческий гейт на
   принятии правил обязателен не только из соображений доверия.

## 6. Экономика контекста: количественная опора

* Стоимость задачи для кодового агента: **$0.03–$2.60**, причём **бóльшая часть счёта —
  контекстный оверхед** (системные промпты, карты репозитория), а не сам сгенерированный код.
* Иерархическая архитектура (дешёвые модели на воркерах, фронтир только на оркестраторе):
  **97.7% точности при ~61% стоимости**.
* Решение о компактификации по факту, а не по порогу: выигрыш до 18.1 пункта на
  математике и 5–9 на агентном поиске при **на 30–70% меньшей стоимости** за вопрос.
* Контекстное окно трактуется как **бюджет на ход**, а не как «ведро».

**Следствие:** тезис «контекст-бандл под задачу вместо чтения всего» имеет прямое
денежное выражение и уже подтверждён отраслевой практикой. Это самая
доказуемая часть нашей ценности.

Локальное подтверждение: в самом WorkTask `.ai/PROJECT_CHECKPOINT.md` уже 128 КБ и
читается в начале каждой сессии — ровно тот антипаттерн, который оплачивается
токенами на каждом запуске.

## 8. Белое пятно

Пересечение, которое **не занято никем** из найденных игроков:

1. **Несколько проектов** одного владельца (агентство, студия, серийный основатель,
   продуктовая компания с 5–20 репозиториями) — оркестраторы работают с одним репо,
   трекеры не переносят метод, spec-фреймворки живут внутри одного проекта.
2. **Переносимый метод + накопление уроков между проектами** с промоушеном
   (проект → стек-пак → ядро) и деградацией плохих правил.
3. **BYO agent** — не привязка к одному вендору (в отличие от BugBot/Cursor,
   Kiro/AWS, Agent HQ/Copilot-центричности).
4. **Brownfield-ориентация** — там, где проваливаются все и где сидит основная боль.
5. **Измеряемая экономика** — токены на задачу, доля переделок, доля регрессий как
   первоклассные метрики продукта, а не побочный эффект.

Формулировка позиционирования-кандидата:

> Не «борд для агентов» и не «ещё один spec-фреймворк», а **инженерная память,
> переносимая между вашими проектами**: она делает агента дешевле и предсказуемее
> на существующих кодовых базах и учится на ваших собственных повторах.

## 9. Угрозы (ранжированы)

1. **GitHub Agent HQ** забирает control plane. Митигация: не конкурировать за «окно»,
   интегрироваться; ценность — в переносимом знании и методе, не в UI назначения задач.
2. **Метод бесплатен.** ~250 000 звёзд у бесплатных фреймворков. Митигация: продавать
   не метод, а накопление + измеримую экономику; метод может быть открытым.
3. **Негативный консенсус вокруг SDD.** Митигация: пропорциональность процесса,
   отказ от церемоний на мелких задачах, цифры вместо проповеди.
4. **Кошелёк занят токенами** ($200–600/dev/мес). Митигация: позиционировать как
   сокращение этих расходов, а не как дополнение к ним.
5. **Холодный старт обучения.** У соло-пользователя мало сигнала. Митигация: готовые
   stack packs из коробки + обучение с первого проекта, а не с десятого.
6. **Риск самоэволюции** (см. «Zombie Agents»). Митигация: человеческий гейт,
   провенанс каждого правила, версионирование и откат ядра.
7. **Вендоры доедают прослойку** (Cursor учится, Linear/Jira ставят агентов).
   Митигация: агент-агностичность как принципиальная позиция.

## 10. Сегменты (кому продавать)

| Сегмент | За | Против |
|---|---|---|
| Соло / инди | много проектов, боль реальна, быстрый цикл продаж | низкая платёжеспособность, конкуренция с бесплатным OSS, мало сигнала для обучения |
| **Агентства, студии, серийные основатели (5–20 репо)** | **мультипроектность — их родная боль; метод обязан переноситься; платят за предсказуемость перед клиентом; данных для обучения достаточно** | сегмент чувствителен к цене, нужен быстрый time-to-value |
| Продуктовые команды 10–50 | бюджеты есть, стандартизация нужна | конкуренция с Linear/Jira/Agent HQ в лоб |
| Enterprise | самые большие чеки | занято (Port, Overcut, Augment, Devin), длинные циклы, SOC2/VPC требования |

Рекомендуемый ICP для первой волны — **агентства и серийные разработчики продуктов**:
их боль ровно мульти-проектная, они уже используют агентов, они измеряют стоимость,
и никто из найденных игроков к ним не адресуется.
